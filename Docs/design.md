# 디자인 시스템 — VeriHop 데모 UI

프런트 작업(4분할 실시간 시각화) 전에 먼저 정의. 대상은 `apps/streamlit_app.py`.
주제는 지식그래프 기반 결정적 검증(Quad Verification) — 장난감 챗봇이 아니라 **검증 콘솔**로
읽혀야 한다. 한국어가 주 언어라 한글 커버리지가 좋은 서체를 우선한다.

## 색

| `--surface-2` | `#1A1F2B` | 카드·hover |

## 타이포그래피

한국어 커버리지가 최우선이라 Inter/Space Grotesk류 서구 기본값은 배제.

- **UI/본문**: **Pretendard** (한글 가변폰트, 현대적이고 기술적인 인상, 한국 개발자 생태계에서
  이미 검증된 품질). 굵기 400(본문)/600(강조)/700(헤더) 사용.
- **기술 데이터(hop trace의 relation명·score·엔티티 원문·라틴 문자/숫자)**: **JetBrains Mono**.
  한글은 모노스페이스 글꼴이 없어도 Pretendard 자체가 글자폭이 고르게 나와 "기술적" 느낌이
  자연히 남는다 — 한글엔 별도 모노 폰트를 억지로 안 씌운다.
- 폰트는 `@font-face`로 데이터 URI 인라인(인터넷 접속 불확실한 배포 환경 대비) 대신, 로컬
  실행 데모이므로 Google Fonts CDN 링크를 CSS에 직접 삽입해도 무방(Streamlit은 CSP 제약 없음).

### 스케일
| 용도 | 크기 | 굵기 | 자간 |
|---|---|---|---|
| 페이지 타이틀 | 28px | 700 | -0.01em |
| 패널 헤더(arm명) | 15px | 600 | 0.02em, 대문자 |
| 본문 | 14px | 400 | normal |
| 캡션/메타 | 12px | 400 | normal |
| 기술 데이터(mono) | 13px | 500 | normal |

본문 가독 폭은 65자 내외 유지(패널이 좁으므로 자연히 지켜짐).

## 간격

4px 기준 스케일: `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`.
패널 내부 카드 사이는 12px, 패널 간 거터는 16px, 섹션 간(계획→trace→최종답) 24px.

## 레이아웃

```
┌─────────────────────────────────────────────────────────┐
│  질문 입력 바 (채팅형 — 하나의 입력, 4-arm 동시 실행)        │
├───────────┬───────────┬───────────┬───────────────────────┤
│ Baseline  │Agent-basic│ Ours−G    │ Ours                  │
│ (회색)    │ (호박)    │ (보라)    │ (청록)                │
│           │           │           │                       │
│ 상태 인디 │           │           │                       │
│ 케이터    │  hop별    │  hop별    │  hop별 trace +        │
│ (대기/    │  trace    │  trace    │  그래프 미니뷰         │
│  진행/    │  카드가   │  카드가   │  (노드·엣지가          │
│  완료)    │  실시간   │  실시간   │   실시간으로 생겨나고   │
│           │  누적     │  누적     │   연결됨)              │
│           │           │           │                       │
│ 최종 답   │ 최종 답   │ 최종 답   │ 최종 답               │
└───────────┴───────────┴───────────┴───────────────────────┘
```

4분할은 세로로 4개 컬럼(요청대로) — 각 패널은 독립 스크롤. 좁은 화면에서는 스택으로 전환.

## 컴포넌트 패턴

- **검증 뱃지**: `type ✅ · name ✅ · desc ❌ · backlink 🚫 contradict` — 지금 방식 유지,
  다만 아이콘 색을 상태색 토큰에 맞춘다(현재는 이모지 기본색이라 팔레트 이탈).
  - contradict는 "❌"(오답 취급)이 아니라 별도의 "거부" 아이콘/색으로 — 하드 비토는 실패가
    아니라 "시스템이 제대로 작동해 걸러낸 것"이라 시각적으로 구분해야 한다(프로젝트 핵심 논지).
- **그래프 미니뷰**(Ours 패널 전용, 요청하신 "그래프 생겨나고 연결되고"): 힙(hop)이 resolve될
  때마다 앵커 노드 → 후보 노드들이 페이드인, backlink 검증 통과 시 엣지가 그려짐(초록),
  contradict면 그려졌다가 빨간 X로 끊김. 이건 Chart.js가 아니라 **노드-엣지 그래프 전용
  라이브러리**(vis-network 또는 Cytoscape.js)가 맞다 — Chart.js는 막대/선/파이용.
- **상태 인디케이터**: 대기(회색 점) → 진행중(강조색 펄스 애니메이션) → 완료(체크).

## 다음 결정 필요 (구현 전 확인)

1. **그래프 라이브러리**: vis-network vs Cytoscape.js — 둘 다 `streamlit.components.v1.html`로
   임베드 가능. vis-network가 더 가볍고 애니메이션(노드 페이드인)이 간단, Cytoscape.js는
   그래프 알고리즘·레이아웃이 더 풍부하지만 이 데모엔 과할 수 있음. **vis-network 추천.**
2. **실시간 스트리밍 아키텍처**: 지금 파이프라인(`run_pipeline`)은 끝나야 결과를 한 번에
   반환한다 — hop이 resolve되는 "중간 이벤트"를 UI가 구독할 방법이 없다. 이미 존재하는
   `TracerPort`(JsonTracer, 매 이벤트를 `emit()`으로 쌓음)를 활용해 파이프라인 실행 중
   이벤트를 큐에 흘려보내고, Streamlit이 그 큐를 폴링하며 그래프/trace를 점진적으로
   그리는 구조가 필요하다 — 이건 단순 스타일링이 아니라 구조 변경.
3. **4-arm 동시 실행**: 지금 UI는 arm 하나를 선택해서 실행하는데, 4분할은 4개를 동시에
   돌려야 한다 — 이것도 마찬가지로 4개 스레드/태스크를 띄우고 각각의 진행 상황을 UI가
   동시에 반영해야 한다.
